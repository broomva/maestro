### P20 saga — 3 rounds (the gate earned its keep on an edge-dense parser)
- **R1 (8.5)** → minor: a `!`-prefixed `done.protect` entry inverted the guard via Bun.Glob negation → `protectGlob()` escapes a leading `!`.
- **R2 (6, FAIL)** → **major**: `git diff --numstat` (no `-z`) C-quotes any path with `"`/`\`/tab/newline; `core.quotePath=false` covers only non-ASCII → a quoted protected path slipped the glob = silent tamper false-negative in the floor. Fixed: `--numstat -z` + split-on-NUL (raw paths). Verified vs real git (`od -c`) + dogfooded.
- **R3 (9, PASS)** → both non-regressed. `--no-renames` confirmed load-bearing.

### Reusable lessons (in [[fix-in-edge-dense-file-regresses]] / arc)
- A git-diff **parser is edge-dense** — fixing one edge (negation) surfaced the next (C-quoting). Treat P20 as an unbounded re-verify loop; enumerate the path-quoting edge space up front (`"`/`\`/tab/newline/non-ASCII/binary/rename).
- `git diff --numstat -z` + split-on-NUL is **the** robust way to read paths — never parse non-`-z` output (git C-quotes; a hand-written C-unquoter is itself edge-dense).
- Verify exact git byte format with `od -c` on a real repo **before** coding a parser.
- Bun.Glob honors a leading `!` as negation — neutralize it for any positive-inclusion glob list.
