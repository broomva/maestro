## LOAD-BEARING LESSONS (reusable)
- **Check the ticket's own scope before expanding.** BRO-1913's "Fix" section literally said "emit
  node.updated"; "Out of scope" already deferred the F5 gate to BRO-1805. My durability expansion was
  scope creep the ticket had already scoped OUT. Read the ticket's Fix + Out-of-scope before widening.
- **A runtime that writes a TRACKED file uncommitted dirties the tree and wedges any clean-tree-gated op**
  (`approveMerge` `isClean`). If a fix must advance FS-authoritative state, it must COMMIT it (a git
  transaction), serialized with the other tree mutators (the shared `serializeApprove` lock).
- **A bare `writeFile` of a SCANNED file is a tombstone hazard**: a torn read fails to parse, and if the
  scanner marks the scan `complete`, the node is soft-deleted (vanishes). Scanned files need atomic
  temp+rename (the repo's own `runtime-lock.ts` pattern). Never truncate-write a live-read file.
- **P20 meta (rule-of-many holds):** the gate again caught real, convergent data-integrity blockers past
  green CI + passing tests + a successful dogfood. Two independent strata agreeing is a strong signal.
  The dogfood proved the fix WORKED; P20 proved it BROKE something else (approve). Dogfood ≠ integration-safe.
