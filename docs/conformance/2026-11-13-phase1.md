# Phase 1 live conformance

Run on Linux on 2026-11-13, against Maestro `bbbd60c` (release build). Each harness ran
separately in a temporary git repository and workspace. The workspace and copied credentials
were deleted after evidence was collected. `maestro mcp` is this build's stdio server;
`maestro serve` is its HTTP server.

One detached shell survived the first full runner's timed-out Claude Stop process; it was
identified and stopped. The runner now marks each invocation and kills matching detached
processes during cleanup; a detached-process test and mutation check cover that correction.

## Commands and failure proofs

```bash
PATH="$HOME/.cargo/bin:$PATH" cargo build --release --locked
scripts/conformance/phase1.sh --harness claude,codex,gemini,agy --timeout 300 --evidence-dir /tmp/maestro-phase1-run-evidence
scripts/conformance/phase1.sh --harness codex --timeout 180 --evidence-dir /tmp/maestro-phase1-codex-final
scripts/conformance/phase1.sh --evidence-dir docs/conformance/2026-11-13/proof-spines --prove spines
scripts/conformance/phase1.sh --evidence-dir docs/conformance/2026-11-13/proof-control --prove control
scripts/conformance/phase1.sh --evidence-dir docs/conformance/2026-11-13/proof-support --prove support
PATH="$HOME/.cargo/bin:$PATH" cargo fmt --all -- --check
PATH="$HOME/.cargo/bin:$PATH" cargo clippy --workspace --all-targets --locked -- -D warnings
PATH="$HOME/.cargo/bin:$PATH" cargo test --workspace --locked
bash -n scripts/conformance/phase1.sh
python3 scripts/conformance/test_phase1.py
```

Each proof command exited **1**: the first compared an instance after `pin` with an untouched
instance, the second ran a passing check while treating it as the positive control, and the third
asserted support against a log containing no claim or completion. Their event or comparison
files are in the corresponding `proof-*` directories. The three guard mutations also each made
the guard test fail. A fourth mutation removing the requirement that a block name the control
instance and a fifth removing detached-process cleanup also failed their guard tests. ShellCheck
was unavailable on the host.

The runner accepts `--harness` as a comma-separated selection, `--timeout` in seconds per
process, and `--evidence-dir`. It needs the release binary and the dogfood skill; set
`MAESTRO_DOGFOOD_SKILL` when the latter is not in `~/.codex/skills/dogfood`. For Gemini, the
Vertex project, location and ADC environment can be supplied by the caller; the defaults match
this host's Gemini Vertex wrapper. The runner never invokes Grok.
